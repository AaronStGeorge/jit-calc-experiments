# jit-calc-experiments tests

## Running a specific test suite
There should be a target in the build system for any given suite.

```
cmake --build build --target check-jit-calc-experiments
```

## Running `lit` tests
### what's `lit`?

Most of the tests here use [`lit`](https://llvm.org/docs/CommandGuide/lit.html), an LLVM tool for gold file testing.
Any gold file testing tool will need an expected output, some command to run to generate the expected output, and in most cases some sort of input file.
With `lit`, rather than specifying a “golden” output file for a given input file you tell the tool what output to expect using commands.
The commands vs output file approach cuts down on the volume of output one has to spell out and diff, it's a little more surgical.
You provide commands to `lit` by embedding them as comments in the input file.
For example: `// RUN: some_command %s` and `// CHECK: <expected output>`.
Embedding commands in comments is a little strange but it preserves the ability to run an input file outside of the testing framework as one normally would, so it's nice too.

### Running a suite of `lit` tests
A suite of lit tests can be run just like any other suite of tests.
```
cmake --build build --target my-lit-suite
```

### Running an individual `lit` test

#### tl;dr
Assuming `llvm-lit` is on your `PATH`.
```
llvm-lit build/test --filter=test.mlir
```

#### explanation

Because `lit` needs to know a lot of environment information that's only available at build time, a user will usually interact with `lit` tests through the build system.
For example, to test a compiler you're building `lit` needs to know where the compiler executable will be built.
`lit` gets this information by generating config files during build that it later loads when tests are run.
[There’s a great article on how this works](https://medium.com/@mshockwave/using-llvm-lit-out-of-tree-5cddada85a78), the below diagram is from that article.
`lit` is a python program by the way, that's why all the config files are python.
![out](https://github.com/AaronStGeorge/jit-calc-experiments/assets/2278731/bee0c910-d494-4c6a-a239-a2fedd30fc51)

Because `lit` needs all the config stuff that knows where things are built, to run an individual test you actually need to point `lit` at the python file generated by CMake rather than the test file you want to run (like one might expect).
Say you just want to run [`test.mlir`](https://github.com/AaronStGeorge/jit-calc-experiments/blob/1dd2900/test/slow-roll-fibonacci-2/test.mlir), you would think you would do `llvm-lit test/slow-roll-fibonacci-2/test.mlir`, but actually you would do `llvm-lit build/test --filter=test.mlir`.
